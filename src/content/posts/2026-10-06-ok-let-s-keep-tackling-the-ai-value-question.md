Ok let's keep tackling the AI Value question. I talked about software development yesterday. The paper "Writing Code vs. Shipping Code" found that AI tools, from autocomplete to agentic, dramatically increase productivity and output at the task level. You know, actual code. But those gains nose-dived as you progress through the development cycle from task to review to new release.

10x increase in code only increased releases by 1.2x. This was a huge study and one of the best. The results were clear. AI is adding value at the task level, but not the final output. They posited the review stage was a blocker to increased output.

Another study ("Artificial Intelligence in the Firm: Bottlenecks in Software Production" by Fiona Chen and James Stratton) took a look at Jellyfish, an engineering analytics platform. They reviewed 300 million work events across roughly 700 firms from 2021 to March 2026. That includes GitHub activity, Jira tickets, calendars, and usage logs for Copilot, Cursor, and Claude Code.

They found something VERY similar to "Writing Code vs. Shipping Code," where productivity spiked early in dev cycled, then dropped off:

- AI Agents increased the amount of code by 30%, commits by 20%, and PRs (pull requests) by 23%.

- Final output barely moves. Completed Jira issues and shipped epics increased only slightly, and the change was not statistically significant. For teams using agents, they estimated a max gain of 12% final output vs 30% increase in code creation.

- Employment doesn’t change. Agent use had no meaningful effect on headcount, junior workers, or senior workers; any headcount decline was no more than 2.9%.

- Reviews are the bottleneck. Engineers spend only 30–40% of their time writing code. After agent adoption, review time per pull request rose 49%; pull requests needing changes nearly doubled, from 13% to 25%; comments rose 35%; and the share of employees reviewing rose 14%.

- AI has not solved the review problem. About 80% of firms have tried AI code-review tools, but AI generates only 23% of review comments and comments on just 11% of pull requests. Humans remain the gatekeepers because faulty code is expensive to ship.

Again, we see the Great Divide, between generation and verified output. This is the core problem of AI Value. Increased productivity is not increased value. Coding is like any supply chain. It is only as strong as its weakest link. Right now, the weakest link is verification, which is human review.

The answer to AI Value for software development is a soft and conditional YES. We can say for certain that AI is vastly increasing code generation and output at the task level. But it is not significantly raising final outputs or releases, which is where actual value lives. Let's see if that pattern holds outside of software development...
